# 第 8 节 · Kanban / XP / 敏捷通用实践
> 学完日 2026-07-31 / 掌握度 高（5/5 全对）/ 关联错题：无（本节全对）

## 要点

### 敏捷不止 Scrum
敏捷方法的两大流派：
- **迭代式（Iterative）**：Scrum -- 固定时间盒、周期性产出增量
- **流式（Flow）**：Kanban -- 无固定时间盒、持续流动交付

### Kanban 核心
3 大要素：**可视化 + 限制 WIP + 管理流动**
- 拉动系统（Pull）：下游有空位才拉动上游工作
- **无固定时间盒**（不像 Scrum 的 Sprint）
- 6 大实践：可视化 / 限制 WIP / 管理流动 / 显式策略 / 建立反馈环 / 协作改进

### WIP + 利特尔法则
**利特尔法则**：`WIP = 吞吐量 × 周期时间`

- 减 WIP → 缩短周期时间（更快交付）
- 这是 Kanban 限制 WIP 的理论依据：限制在制品，缩短交付周期

### 度量（4 个核心度量 + CFD）
| 度量 | 含义 |
|---|---|
| 前置时间（Lead Time） | 从请求进入到交付的总时间 |
| 周期时间（Cycle Time） | 从开始做到完成的时间 |
| 吞吐量（Throughput） | 单位时间完成的工作量 |
| 累积流量图（CFD） | 可视化 WIP / 瓶颈 / 趋势 |

### XP（极限编程）
- **5 价值观**：沟通 / 简单 / 反馈 / 勇气 / 尊重
- 工程实践：结对编程 / TDD（测试驱动开发）/ CI（持续集成）/ 重构

### 信息辐射源
- 把关键信息（进度/度量/规则）放在公开可见的物理或电子看板，谁走过都能看清，不靠"问"

### Kanban vs Scrum 对比
| 维度 | Scrum | Kanban |
|---|---|---|
| 时间盒 | 固定 Sprint（1 月） | 无固定时间盒 |
| 角色 | PO / SM / Developers | 无强制角色 |
| WIP | Sprint 内不受限（范围已确定） | 严格限制 WIP |
| 变更 | Sprint 期内原则上不变更范围 | 随时变更（拉动） |
| 度量 | 速率（Velocity） | 前置/周期时间、吞吐量、CFD |

## 易混 / 易错
- Kanban 无固定时间盒、无强制角色：不要把 Scrum 的 Sprint/角色硬套
- 利特尔法则：减 WIP 缩周期（不是减 WIP 提吞吐）
- Scrum 量速率，Kanban 量前置/周期时间 + CFD
- 前置时间 vs 周期时间：前置时间从请求进来算，周期时间从开始做算
