# 第 7 节 · Scrum：角色 / 工件 / 事件
> 学完日 2026-07-31 / 掌握度 高（5/5 全对）/ 关联错题：无（本节全对）

## 要点

### Scrum 的底座：经验主义 3 支柱
Scrum 建立在**经验过程控制**理论之上，3 大支柱环环相扣：
1. **透明（Transparency）**：过程与成果对所有人可见（Product Backlog、进度、DoD 都公开），谁都能看清真实状态
2. **检视（Inspection）**：频繁检查进度与工件，及时发现问题（在 5 个事件中检视）
3. **适应（Adaptation）**：发现偏离时立即调整流程/计划，避免偏离过大

> 没"透明"就没法"检视"，没"检视"就谈不上"适应"

### 335 框架
**3 角色 + 3 工件 + 5 事件** = Scrum 全部骨架。

### 3 角色
| 角色 | 核心定位 | 关键细节 |
|---|---|---|
| **Product Owner（PO）** | 价值最大化者，管 Product Backlog | **一人**、非委员会；可把工作委托他人，但**担责不分开**（最终对产品价值负责） |
| **Scrum Master（SM）** | 服务型领导，消除障碍、促 Scrum 落地 | **不是 PM**、不做产品/技术决策；服务 PO/Developers/组织 |
| **Developers** | 做活的人，自组织 + 跨职能 | 团队规模 **3-9 人**；自组织决定怎么干 |

- 易混点：PO 可授权他人写 Backlog，但出了问题仍是 PO 担责（担责不分开）

### 3 工件 + 承诺
| 工件 | 承诺 |
|---|---|
| Product Backlog | Product Goal（产品长期目标） |
| Sprint Backlog | Sprint Goal（本 Sprint 目标） |
| Increment | DoD（完成的定义） |

- **每个 Sprint 至少产出 1 个满足 DoD 的增量（Increment）**
- DoD 是"做到什么算完成"的质量底线

### 5 事件（时间盒）
| 事件 | 时长上限 | 谁参加 |
|---|---|---|
| Sprint 规划 | 8h（1 月 Sprint） | 全 Scrum Team |
| 每日站会（Daily Scrum） | 15min | **只 Developers** |
| Sprint 评审 | 4h | 团队 + 干系人 |
| Sprint 回顾 | 3h | **只 Scrum Team** |
| Sprint（容器） | 1 月 | - |

- 站会**不是汇报会（status）**：只 Developers 参加、只检视本 Sprint 进展、为下 24h 做调整；发现问题**会后另开小会**解决
- **Sprint 容器不延期**：要么按时结束，要么提前取消；**只有 PO 能取消 Sprint**
- Sprint 是固定时间盒，迭代周期不变

## 易混 / 易错
- PO 可委托但担责不分：授权写 Backlog ≠ PO 甩锅
- SM ≠ PM：SM 服务型领导、消除障碍，不做决策
- 站会 ≠ 汇报会：只 Developers、检视+调整、问题会后另开
- 每个 Sprint 必有增量（满足 DoD），不止"完成一部分功能"
- 取消 Sprint 的唯一角色 = PO
