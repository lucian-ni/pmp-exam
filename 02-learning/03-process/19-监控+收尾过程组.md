# 19 · 监控 + 收尾过程组

> 学完日：2026-08-23 / 掌握度：8/8 全对
> 来源：《过程组实践指南》。过程组模型收官：监控 12 过程 + 收尾 1 过程。
> 主线：执行产**数据** → 监控加工成**信息/报告** → 对照基准找偏差 → 走**整体变更控制** → 回执行落地。

## 监控 12 过程（7.1–7.12）总览
整(2)→领(10)：整合 2 个是总枢纽，其余 10 个按领域管偏差。
| 过程 | 干什么 |
|---|---|
| 7.1 监控项目工作 | 对照计划盯整体；产出**工作绩效信息/报告** |
| 7.2 实施整体变更控制(ICC) | **变更枢纽**：评估/批准/否决所有变更请求 |
| 7.3 确认范围 | 干系人**正式验收**可交付成果 |
| 7.4 控制范围 | 盯范围偏差、防蔓延、管范围变更 |
| 7.5 控制进度 | SV/SPI；赶工/快速跟进 |
| 7.6 控制成本 | CV/CPI；EAC/ETC |
| 7.7 控制质量 | **检查产品**是否符合要求(QC) |
| 7.8 控制资源 | 盯资源实际使用、纠正分配 |
| 7.9 监控沟通 | 确保信息需求被满足 |
| 7.10 监控风险 | 跟踪风险、盯应对、识新风险 |
| 7.11 控制采购 | 监督合同履行、违约索赔、**关闭合同** |
| 7.12 监控干系人参与 | 盯干系人关系、调整策略 |

## 7.2 实施整体变更控制（ICC）⭐
- 所有变更请求唯一入口：记录→评估影响(范围/进度/成本/风险)→决定→更新计划/基准/通知。
- **基准变更(三大基准)→必须 CCB 或授权人批准**；**不影响基准的小变更→PM 自行批准**。
- 全员可提；**否决的变更也记录归档并通知请求人**。
- 批准后：更新计划/基准→回执行落地→监控继续跟踪。

## 7.3 确认范围 vs 7.4 控制范围 ⭐
- **确认=验收**（干系人正式签字，每阶段/交付时点）；**控制=防蔓延**（全程盯白加范围不加钱）。
- 信号：客户签字验收→确认；范围蔓延/变更→控制。

## EVM 公式网（7.5+7.6）⭐
| 指标 | 公式 | 含义 |
|---|---|---|
| SV | EV−PV | 正超前/负落后 |
| SPI | EV/PV | >1 好 |
| CV | EV−AC | 正省钱/负超支 |
| CPI | EV/AC | >1 好 |
| EAC | BAC/CPI(典型) 或 AC+(BAC−EV)(非典型) | 预计总花费 |
| ETC | EAC−AC | 还要花多少 |
| TCPI | (BAC−EV)/(BAC−AC) | 剩余钱做剩余活的难度 |
- **抓 EV**（干成的活值多少钱）就抓住 EVM。
- 纠偏：**赶工**(加资源增成本) / **快速跟进**(并行增风险)。

## 领域 6 个监控过程要点
- 7.7 控制质量 QC=**查产品**；对照 6.3 管理质量 QA=**管过程**。控制图：**连续 7 点同侧=失控倾向**→查系统原因。
- 7.8 控制资源：计划 vs 实际，纠正失衡。
- 7.9 监控沟通：确认干系人**收到**信息（非发出即完）。
- 7.10 监控风险：跟踪+盯应对+识新+评估过程；工具=风险审计/储备分析/状态会。
- 7.11 控制采购：合同履行/付款里程碑/违约索赔/合同变更/**关闭合同**。
- 7.12 监控干系人参与：跟踪参与水平、评估策略有效性。

## 收尾 8.1 结束项目或阶段（唯一 1 个）
- **收尾 6 件套**：①移交最终可交付成果 ②干系人最终验收签收 ③正式关闭合同(联动7.11) ④更新组织过程资产(归档) ⑤总结经验教训(经验教训登记册) ⑥释放团队资源；另告知干系人收尾。
- **收尾前提**：范围完成 + 干系人验收 + 合同关闭，三者缺一不可。

## 易混 / 易错
- 数据(执行)→信息(监控分析)→报告(呈现) 链条别乱。
- 确认范围(验收) vs 控制范围(防蔓延)；QA(6.3管过程) vs QC(7.7查产品)。
- 变更：基准→CCB，小变更→PM 批；否决的变更也记录。
- EVM：SV/CV 看正负，SPI/CPI 看与 1 的大小。
