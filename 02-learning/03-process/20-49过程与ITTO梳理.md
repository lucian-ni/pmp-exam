# 20 · 49 过程与 ITTO 梳理

> 学完日：2026-08-24 / 掌握度：8题 7/8 + 变式 1/1（错"核实的 vs 验收的"，变式纠对）
> 来源：《过程组实践指南》§1（过程联系、数据信息术语、表 1-4）。概念为主，不逐条背 ITTO。
> 主线：**输出 -> 输入**把 49 个过程串成网络；五条黄金主线 + 登记册族是全部考点。

## ITTO 是什么
- 每个过程 = **输入**(原材料：文件/数据/环境因素) + **工具与技术**(加工手段：专家判断/会议/数据分析) + **输出**(成果：文件/可交付成果/变更请求/更新)。
- 指南原话：过程通过具体的输入和输出相互联系，一个过程的成果可能成为**另一个过程（可跨过程组）**的输入。过程是网络节点，不是流水线孤岛。
- **过程组 ≠ 项目阶段**：阶段是时间切片，过程组是逻辑分组；项目分多个阶段时，每个阶段可把 5 个过程组完整走一遍。

## 五条黄金主线 ⭐
1. **授权链**：立项文件/协议 -> 制定项目章程(**输出章程**) -> 章程作为几乎所有规划过程的输入 -> 汇成项目管理计划。
2. **计划链**：各领域子计划 + 三大基准 -> 制定项目管理计划(整合) -> 批准后指导执行。
3. **数据-信息-报告链**（指南 §1.8 原文定义）：
   - **工作绩效数据** = 执行中从活动中收集的**原始观察结果和测量值**（完成%、实际成本、缺陷数、变更请求数）
   - **工作绩效信息** = 各**控制过程**把数据结合背景和跨领域关系**整合分析**后所得（可交付物状态、预测 ETC）
   - **工作绩效报告** = 监控项目工作把信息**汇编**成供决策的实物/电子文件（状况报告、备忘录、电子仪表盘）
   - 流向：数据(执行产出) -> 信息(控制过程加工) -> 报告(监控汇总) -> 决策/行动/变更
4. **变更闭环**：执行或监控中**提出**变更请求 -> 实施整体变更控制(评估影响、CCB 决策) -> 批准则**更新计划/基准** -> **批准的变更请求作为输入回到指导与管理项目工作**落地 -> 监控核实；否决也记录归档并通知。
5. **交付验收链**：可交付成果(执行产出) -> 控制质量 -> **核实的可交付成果**(内部质检合格) -> 确认范围 -> **验收的可交付成果**(客户正式签字) -> 收尾移交。

## 登记册族（随过程链逐轮细化）
- 干系人登记册(识别)->参与评估矩阵；风险登记册(识别->定性排序->定量数值->应对计划，每步更新)；问题日志(管理团队/干系人)；经验教训登记册(执行中持续记 -> 收尾归档进组织过程资产)。

## 怎么考 / 判别信号
- **先后顺序题**：情景问"下一步该什么"，沿主线走，勿跳步（如未质检的成果不能直接让客户验收）。
- **数据vs信息vs报告**：原始测量值=数据；结合背景的分析结论=信息；汇编给决策层的=报告。
- **核实的vs验收的**：QC 在前(内部)、确认范围在后(客户)；先核实后验收。
- **变更请求谁提出**：执行/监控过程提出，ICC 只**处理**(评估+批准/否决)，不提出。
