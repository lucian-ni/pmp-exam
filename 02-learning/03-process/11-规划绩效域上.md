# 第 11 节 · 规划绩效域（上）：范围/进度/成本
> 学完日 2026-08-05 / 掌握度 高（6/6 全对）/ 关联错题：本节无新错题

## 定位
8 绩效域第三个（"干团开**规**项交测不"的"规"），PMBOK7 §2.4。涵盖为交付项目可交付物和成果所需的"**初始+持续+演变**"的组织和协调活动。**核心视角**：规划是演进的、与开发方法匹配的，非 upfront 一次定死。

## 预期成果（5 条）
1. 项目有条理、协调、周密考虑地推进
2. 有交付项目成果的**整体方法**
3. 对不断演变的信息做详细说明以生成可交付物
4. 规划花费时间**适合**情况（不过度、不不足）
5. 规划信息足以**管理干系人期望**；有调整计划的过程

## 规划概述（§2.4.1）
- 规划目的：积极主动制定方法创建可交付物
- 高层级规划可在项目**批准之前**开始
- 三重底线（社会/环境/财务）+ **产品生命周期评估**（评估潜在环境影响）为设计提供信息
- **规划工作量适当**：过度=低效；不足=信息不足以决策/管理期望

## 规划的变量（§2.4.2，5 项 -> 决定规划多少/何时/多频繁）
开发方法 / 项目可交付物 / 组织需求 / 市场条件 / 法律法规
- 建筑->大量前期规划；高技术->持续适应；竞争激烈->最少前期抢上市；法规->先有特定文件

## 交付与范围（§2.4.2.1）
### 产品范围 vs 项目范围
| | 定义 | 回答 |
|---|---|---|
| 产品范围 | 产品/服务/结果的**特性和功能** | 做出的东西有什么功能 |
| 项目范围 | 为交付规定特性产品而**必须完成的工作** | 要做哪些事才能交付 |
- 电商：产品范围=购物车/支付等功能；项目范围=调研/设计/开发/测试/部署等工作

### 预测 vs 适应分解
- 预测型：可交付物 -> 范围说明书 + **WBS** -> 工作包
- 适应型：主题/史诗故事 -> 特性 -> 用户故事 -> 待办列表；优先级排序减不确定性

### 负责的最后责任时刻（Last Responsible Moment）
- 推迟决策到"**再推迟则成本超过收益**"
- 保留多个选项、不为可能变/不需要的工作做计划 -> 减少浪费
- ⚠️ 非"越晚越好"，是最后可负责时刻

## 估算（§2.4.2.2）
### 四方面（生命周期影响）
| 方面 | 含义 | 演进 |
|---|---|---|
| 区间 | 估算值可能范围 | 开始大(-25%~+75%)，后期小(-5%~+10%) |
| 准确度 | 正确性（接近真值） | 开始低，后期高 |
| 精确度 | 精准度（粒度） | 应与准确度匹配 |
| 信心 | 对估算的信心 | 随经验增；新技术低 |

### ⚠️ 准确度 vs 精确度（最高频易混）
- 准确度=对不对（打靶：中心在不在靶心）=估算的**正确性**
- 精确度=细不细（打靶：弹孔密不密；2天 vs 本周某时；取整到千元）
- 独立：可"准确度低但精确度高"（密集但偏离靶心，图 2-15）
- "2 天"比"本周某时"更精确但不一定更准确
- 精确度应与准确度匹配，勿用假精确制造虚假信心
- **区间怎么用**：准确度越低，潜在区间越大（PMBOK7）。这是**同一份估算**信息变多以后会收窄，对应准确度提高（初期 -25%~+75% → 后期 -5%~+10%）。**不是**两个估算师同时报不同宽窄，就能判谁更「对」——不知真值不能比准确度。
- 覆盖率≠准确度：宽区间更能盖住真值，不等于更准

### 估算 5 方法
1. **确定性 vs 概率**：确定性=点估算（36 个月）；概率=区间+概率。蒙特卡洛三要素=①点估算+区间 ②置信水平(95%) ③概率分布
2. **绝对 vs 相对**：绝对=具体数字（120 小时）；相对=**计划扑克牌+故事点**（与已知工作比较）；不同项目故事点不可比
3. **基于工作流**：周期时间 + 产量
4. **调整对不确定性**：应急时间/资金

## 进度（§2.4.2.3）
- 进度计划=执行项目活动的**模型**（非简单时间表）

### 预测型 5 步
分解活动 -> 排序 -> 估算人力投入/持续时间/资源 -> 分配资源 -> 调整至一致

### 进度压缩
| 方法 | 手段 | 代价 |
|---|---|---|
| 赶工 Crashing | 增加资源以最小成本压缩（加人/加班/付费） | 花钱，风险低 |
| 快速跟进 Fast tracking | 顺序活动改部分并行 | 增风险/返工，需用提前量滞后量 |
口诀：赶工花钱买时间，快速跟进并行增风险

### 提前量 vs 滞后量
- 提前量 Lead=加速紧后（FS-1）
- 滞后量 Lag=延迟紧后（FS+1，非等待是逻辑调整）

### 4 种依赖关系
| 类型 | 定义 | 能否改 |
|---|---|---|
| 强制性 Mandatory | 合同/工作内在性质 | ❌ 不能（硬逻辑） |
| 选择性 Discretionary | 最佳实践/偏好 | ✅ 能（软逻辑） |
| 外部 External | 项目与非项目活动间 | ❌ 不能 |
| 内部 Internal | 项目活动间 | ✅ 能 |
口诀：**强外不改、选内可改**。注意"团队内部安排"=内部可改（非强制）

### 适应型进度
- 层级：产品愿景 -> 路线图 -> 发布计划 -> 迭代计划
- 远期保持高层级，避免据早期反馈改远期规划
- 时间盒：优先级待办 -> 估算 -> 自管理完成 -> 展示 -> 更新重排

### 人力投入驱动 vs 固定持续时间
- 人力投入驱动=加人可缩时（建房子），有临界点超过反延长（协调/沟通/返工）
- 固定持续时间=加人没用（运行测试/培训）
- 无固定公式算加几个人缩短多少

## 预算（§2.4.2.4）
### 组成（由内到外）
```
工作成本估算（按活动）
  ⊂ 成本基准 = 工作成本估算 + 应急储备
    ⊂ 项目预算 = 成本基准 + 管理储备
```
- 成本基准按时间段分配 -> S 曲线；资金有限 -> 重排工作

### ⚠️ 应急储备 vs 管理储备（最高频易混）
| | 应对 | 在基准内 | 谁管 |
|---|---|---|---|
| 应急储备 | **已识别**风险 | ✅ 在基准内 | PM 可动用 |
| 管理储备 | **未识别/范围内意外** | ❌ 基准外（在预算内） | 组织/发起人/PO/PMO，PM 需审批 |
口诀：应急=已识别+基准内；管理=未知意外+基准外需审批

## 易混 / 易错
- **准确度 vs 精确度**：对不对 vs 细不细；精确数字≠更准确；不知真值不能比两个估算谁更准；宽更能盖住≠更准；同一项目后期收窄才是准度提高
- **应急 vs 管理储备**：已识别在基准内 vs 未知在基准外需审批
- **赶工 vs 快速跟进**：花钱买时间 vs 并行增风险
- **4 依赖**：强外不改、选内可改；"团队内部安排"=内部可改非强制（陷阱项）
- **产品范围 vs 项目范围**：特性功能 vs 必须完成的工作
- **计划扑克牌/故事点=相对估算**；不同项目故事点不可比
- **最后责任时刻**：非越晚越好，是"再拖就产生成本"那一刻
- **人力投入驱动有临界点**：加人超过临界反延长
- **规划工作量适当**：过度低效、不足不足以决策
- **概率估算三要素**：点估算+区间 / 置信水平 / 概率分布
