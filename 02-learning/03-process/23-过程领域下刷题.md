## 定位
上半管「活怎么规划、怎么改、怎么尽早交」。下半管「活在跑的时候怎么盯、怎么收」。

**入口** = 这件事被允许进入项目的正规通道（谁收、记到哪、谁批），不是职权本身变了。先看生命周期，是因为通道长什么样取决于方法：预测改基准→CCB；适应改待办→PO；混合看改的是哪一块。

## 过程题操作系统（下）
- 特别沟通请求暴增 = 沟通规划不足：改计划、改参与入口，不让团队挨个回
- 风险=还没发生（登记册+应对）；问题=已经发生（问题日志+解决）
- 应急计划预先写好，实施若动基准仍走变更；权变=事先没计划的现场处置
- 采购：PM 通常不签合同；RFI 问信息 / RFP 要方案 / RFQ 要比价；报价异常先要成本结构
- 工件单一真相来源；历史信息优先找 PMO / 组织过程资产
- 治理=谁有权批什么（CCB / 发起人 / 阶段门），越权先回到治理
- 显性可编、隐性跟学；项目临时，收尾必须转移
- 阶段收尾 ≠ 项目收尾；项目已关，先核知识转移/合同，不把运营问题当项目执行去修

## 易混
- 风险 vs 问题 vs 经验教训 vs 变更日志（未发生 / 已发生未解决 / 已发生已处理要留给后人 / 改基准）
- 应急计划 vs 权变措施（预先准备 vs 来不及批准的现场动作）。**权变 = Workaround，不是「权力变了」**
- 阶段验收 vs 项目最终产品验收
